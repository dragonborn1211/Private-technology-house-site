# Private Technology House — сайт-портфолио

Документация для Claude Code. Прочитай целиком перед любой правкой. Сайт держится на нескольких
неявных договорённостях между разметкой, CSS и движком частиц. Если нарушить хоть одну, сборка
блока сломается тихо, без ошибок в консоли.

## Что это

Одностраничный сайт студии «Private Technology House» с тёмной холодной палитрой «Ледник». Главная
фишка — весь сайт **собирается из частиц**:
- первый экран при загрузке;
- каждый следующий блок, когда доезжает до экрана при прокрутке.

Частицы обводят блоки, ложатся полосками строк, складываются в буквы, и только потом проявляется
настоящий текст.

- **Файлы сайта** (сборки, зависимостей и фреймворков нет, всё подключается напрямую):
  - `index.html` — только разметка;
  - `assets/site.css` — все стили;
  - `assets/scroll.js` — мягкая прокрутка колесом (`window.PTScroll`) и свой скроллбар `[data-sbar]`;
  - `assets/previews/*.jpg` — снимки сайтов для превью (обновляет `node tools/previews.mjs`);
  - `assets/scenes.js` — сцены в карточках (`makeMini`, `makeFlow`, `makeFlowLight`), отдаёт `window.PTScenes`;
  - `assets/engine.js` — движок частиц `factory(root)`. Подключается после `scenes.js`.
- **Бэклог** задач и известных недочётов — `BACKLOG.md`.
- **На хостинг** выкладываются только `index.html` и `assets/`. Документация и `tools/` сайту не нужны.
- **Репозиторий:** `github.com/dragonborn1211/Private-technology-house-site`, ветка `main`, **публичный**. Светлая
  версия сайта лежит там же в ветке `light`. Не попадают в git (`.gitignore`): `TASK.md` (исходное ТЗ, в нём есть
  слова из раздела «Кейсы: правовое ограничение»), `tools/forbidden.local.txt`, скриншоты `tools/shots*`,
  `node_modules/`.
- **Внешнее:** только Google Fonts — Manrope 300–600, Cormorant Garamond italic 500, JetBrains Mono 400/500.
- **Язык страницы:** русский (`lang="ru"`).
- **Есть похожая светлая версия.** Её здесь нет, и в задачах её не трогаем.

## Слои (z-index)

```
z 0   <canvas data-pt-smoke>   fixed — дымный след курсора, лежит ПОД контентом
      секции и контент          обычный поток
z 30  <canvas data-pt-canvas>  fixed — WebGL-частицы, pointer-events: none
z 35  .sbar[data-sbar]         fixed — свой скроллбар у правого края
z 40  пульт внизу              fixed — [data-pt-step], [data-pt-replay], [data-pt-prog]
```

Ничего не ставь выше z 40, кроме модалок. Холсту частиц нельзя давать pointer-events.

## Структура страницы

```
#pt-site.pt                      корень; JS вешает .pt-on, а после старта сетки .g-on
├─ .pt-grid                      12 колонок .pt-col + 2 краевые линии .pt-edge (фон)
├─ canvas[data-pt-smoke]
├─ canvas[data-pt-canvas]
├─ section.sec[data-sec=hero]        #top         data-pt-burst
├─ section.sec[data-sec=directions]  #directions  — 4 карточки направлений
├─ section.sec[data-sec=objects]     #objects     — заголовок блока + ряд 02.1 «Сайты» (Resonara, Antares, «ваш проект»)
├─ section.sec[data-sec=automation]  #automation  — ряд 02.2 «Автоматизация» (2 схемы + «ваш процесс») + «Все объекты →»
├─ template[data-hidden-section=integrations] — СКРЫТ: ряд 02.3 «Интеграции» (2 схемы + «ваша интеграция»)
├─ section.sec[data-sec=process]     #process     — 4 этапа
├─ section.sec[data-sec=pricing]     #pricing     — 3 тарифа, цены-заглушки [цена]
├─ section.sec[data-sec=contact]     #contact     data-pt-burst — призыв + футер
├─ пульт (fixed)
└─ .sbar[data-sbar] (fixed)      свой скроллбар
```

**Скрытые блоки.** То, что временно убрано со страницы, но должно сохраниться, лежит в `<template>`: сейчас там
ряд «Интеграции» (`data-hidden-section="integrations"`) и карточка «Поток» (`data-hidden-card="flow-lock"`).
Движок содержимое `<template>` не видит: секция не собирается, сцены не создаются. Чтобы вернуть блок, перенеси
разметку из `<template>` прямо в HTML. Не вставляй её через JS после старта (ловушка 1). Вместе с «Интеграциями»
кнопку «Все объекты →» нужно вернуть из `automation` в конец `integrations`.

Сетка: `max-width: 1440px`, боковой отступ `clamp(20px, 5vw, 80px)`, `column-gap: 24px`. Брейкпоинт
мобилки `760px`: остаются 4 колонки, прячутся `.nav`, `.hide-m`, `.an`.

**Прокрутка** (`assets/scroll.js`). Привязки к секциям нет.
- Колесо и тачпад двигают цель, а страница плавно догоняет её: доля пути `LERP = 0.08` за кадр при 60 fps.
  Чем меньше число, тем мягче.
- Якорные ссылки `#…` едут к секции по `easeInOutCubic` за 0.8–1.8 с и пишут хеш в историю.
- Тач, клавиатура и поиск по странице прокручивают нативно, модуль подхватывает их позицию.
- При `prefers-reduced-motion` вся прокрутка нативная.
- Кадр прокрутки — `PTScroll.tick(now)`. Его первым делом вызывает `frame()` движка, поэтому частицы не отстают от
  контента. Пока страница едет, у модуля есть и свой rAF; работа выполняется один раз за кадр.
- **Программная прокрутка** — только `window.scrollTo({ top, behavior: 'instant' })` или `PTScroll.to(y)`. Без
  `behavior` сработает CSS `scroll-behavior: smooth`, и он будет спорить с модулем.

Нативная полоса прокрутки скрыта (`scrollbar-width: none`). Вместо неё своя: тонкая, с градиентом акцентов. Она
появляется только при прокрутке и гаснет через 1.2 с после остановки. Ползунок можно тянуть, клик по дорожке
листает на экран.

Блок «Объекты» — три секции подряд, чтобы каждая собиралась из частиц отдельно (см. ловушку 6). У `automation`
и `integrations` верхний отступ меньше обычного: `clamp(48px, 7vh, 80px)`. Ряд = шапка `div.blk.fr.ln.row-h`
(моно-подпись `02.N / …` + строка `.row-t`) и сетка `div.blk.obj-grid` с карточками `.glass.fr.obj`
(окно 4:3, под ним `.obj-tx`: подпись `.mono`, заголовок `.obj-h`, описание `.obj-d`).

## Контракт разметки ↔ движок (САМОЕ ВАЖНОЕ)

Движок ничего не знает о конкретном контенте. Он читает DOM по этим правилам:

| Что | Правило |
|---|---|
| **Секция** | `<section class="sec" data-sec="имя" id="якорь">`. Каждая `data-sec` собирается отдельно, по очереди. На секцию вешаются стадии `s-wire` → `s-skel` → `s-text` → `s-done`. |
| **Финал сборки** | `data-pt-burst` на секции — после сборки частицы разлетаются по экрану («взрыв»). Сейчас атрибут стоит только у `hero` и `contact`. У остальных секций финал тихий (`phSettle`): частицы гаснут на месте, а пыль проявляется без разлёта. |
| **Блок** | Обёртка `class="blk" data-blk`. Первым ребёнком идёт `<span class="wf" aria-hidden="true" data-pt-skip><span class="wf-l">&lt;tag&gt;<b data-wf-size></b></span></span>`. Это уголки каркаса и подпись с реальным размером; размер JS подставляет сам. Частицы обводят каждый `[data-blk]`. |
| **Рамка** | Любой элемент с фоном или рамкой, который должен «проявиться», получает класс `fr`. До стадии `s-skel` CSS делает его прозрачным, частицы обводят его по контуру с учётом `border-radius`. `data-fr-line="top"` — только верхняя линия (для разделителей). `data-fr-color="accent"` — частицы рамки голубые. |
| **Текст** | При старте `markText()` один раз обходит все текстовые узлы в секциях и вешает на родителя класс `.ptx`. Такой текст скрыт (`opacity: 0`) до `s-done`, а частицы складываются в его буквы. Шрифт, размер и цвет берутся из computed style, то есть буквы частиц совпадают с настоящими. |
| **Исключение** | `data-pt-skip` на элементе: всё внутри не прячется и не превращается в частицы. Обязательно для подписей каркаса `.wf`, аннотаций `.an` и любого текста, который меняет JS (подписи мини-сцен, счётчики). |
| **Аннотации** | `<span class="an" data-pt-skip style="top/left…">css-подсказка</span>` внутри `.blk`. Видны только в стадиях `s-skel` и `s-text`. Это «код» во время сборки. |
| **Градиентный текст** | `class="it"` (курсив Cormorant, переливается) + атрибут `data-grad="#8ED8F8,#7FA8FF,#B7A6F2,#F6F8FA,#9FE5D1"`. Атрибут нужен движку: по нему частицы букв красятся градиентом. Все `.it` переливаются с одной скоростью (4 с). Разнесены по фазе через `style="animation-delay: -Ns"`. |
| **Списки** | `ul.list > li`. Тире-маркер красится переменной `--c` с карточки и появляется в `s-done`. |

### Ловушки

1. **Текст, добавленный после старта** (`innerHTML`, `appendChild`, `textContent` у нового узла), не
   получит `.ptx`. Он будет виден сразу и не соберётся из частиц. Новый статичный текст пиши в разметку.
   Динамический текст оборачивай в `data-pt-skip`.
2. **Текст внутри `<canvas>`-сцен и их подписи** — всегда в `data-pt-skip`. Иначе движок спрячет
   подпись и попробует собрать её из частиц.
3. **Не используй `display: none` для контента секции на десктопе.** Скрытый текст движок пропустит,
   но при показе он останется с `opacity: 0` (`.ptx`) до следующей сборки.
4. **Высоту и раскладку нельзя менять после того, как секция начала собираться.** Частицы летят в
   координаты, измеренные в момент стадии.
5. **Новый градиентный текст без `data-grad`** соберётся из частиц одного цвета, а потом «вспыхнет»
   градиентом. Это заметно.
6. **Чем больше текста в секции, тем реже частицы на каждой букве.** Всего частиц 26 000 на десктопе и
   14 000 на мобилке. Если секция очень длинная (выше ~1,5 экрана), лучше разбить её на две `data-sec`.

## Движок: как идёт сборка

Движок — одна функция `factory(root)` в `assets/engine.js`. Её вызывают для `#pt-site`. Сцены в карточках живут
отдельно, в `assets/scenes.js`, и получают от движка объект `env` с живыми `rm`, `mob`, `vh`.

### Порядок

0. До старта движка на `#pt-site` стоит класс `pt-boot` (он прописан в разметке). Пока скрипты грузятся, он прячет
   секции и отключает переходы. Без этого браузер успевает нарисовать готовую страницу, и она гаснет поверх вспышки.
   Не убирай `pt-boot` из разметки. Его снимает движок, а при сбое — обработчик ошибки и `onerror` у `engine.js`.
1. `markText()`, затем `.pt-on`, затем снятие `pt-boot`, затем `initGL()` (WebGL; при отказе — 2D-фолбэк).
2. `request(hero)`. Остальные секции ставятся в очередь через `IntersectionObserver` (`rootMargin` снизу −18%).
3. `pump()` берёт секции из очереди строго по одной. Если секцию пролистали вверх, не дождавшись её
   сборки, она сразу помечается `s-done`.

### Первый экран, `runHero` (секунды)

Все времена умножаются на `HERO_K = 0.75`, 1 — исходный темп. Владелец утвердил именно этот темп: короткую версию
при повторной загрузке пробовали, и она слишком быстрая. В таблице уже с множителем.

| t | Что происходит |
|---|---|
| 0 | вспышка частиц из центра |
| 0.45 | `.g-on`, частицы на линии сетки |
| 1.2 | `s-wire`: каркас |
| 2.0 | `s-skel`: стили и сканер |
| 2.8 | `s-text`: буквы |
| 3.95 | `s-done`: текст проявлен, часть частиц (`OBJ`, 30%) уходит в объект |
| 4.35 | финал (`finish`) |

### Перезагрузка в середине страницы и быстрая прокрутка

- Если первый экран уже пролистан (браузер вернул прокрутку), он помечается собранным, и срабатывает `skipHero()`:
  включается сетка, частицы объекта сразу встают на место.
- Если вспышки не было вовсе, `seed()` невидимо раскладывает частицы по текущему экрану. Иначе они летели бы из
  точки (−999, −999).
- Если собираемая секция целиком ушла с экрана, а видимые секции ждут в очереди, `abortRun()` дособирает её
  мгновенно. Таймеры прерванной сборки отменяет `runId`: все стадии ставь через `atRun`, а не через `at`.

### Остальные секции, `runSec`

Все времена умножаются на `SEC_K = 0.9`. Значение подобрано с владельцем: `0.5` слишком быстро, «не успеваешь
понять, что произошло», `0.75` тоже быстровато. Темп одинаковый для всех секций. Раньше при очереди он ускорялся
×0.6, и соседние блоки собирались вразнобой (2.06 / 1.24 с). В таблице уже с множителем, разброс `sweep`
масштабируется темпом текущей сборки (`runK`).

| t | Стадия |
|---|---|
| 0 | `s-wire` |
| 0.68 | `s-skel` |
| 1.35 | `s-text` |
| 2.48 | `s-done` + хук `wakeSites(section)` |
| 2.79 | финал (`finish`) |

**«Пересобрать блок»** — режим показа. Кнопка пересобирает **все секции, которые видны на экране**, а не одну:
иначе соседний блок оставался нетронутым, и казалось, что часть контента не исчезает.
- Сначала 1 с текст верхней секции рассыпается частицами, на 1.0 с все видимые секции разом очищаются.
- С 1.7 с секции, занимающие от 12% высоты экрана, собираются заново сверху вниз, по очереди, в полном исходном
  темпе `PRESENT_K = 1` (у первого экрана тоже).
- Узкие полоски у края экрана (флаг `instant` в очереди) проявляются сразу после них, без частиц: иначе основной
  блок ждал бы сборки полоски. Сцены в карточках на время
пересборки гаснут вместе с текстом (CSS по `.sec:not(.s-done)`) и засыпают (`sleep()`). Когда блок собран, они
собираются заново (повторный `wake()`).

### Пропуск сборки (`skipNow`)

Первый экран мгновенно собирается от прокрутки (колесо или тач), клика или клавиши. Остальные секции — только от
клика или клавиши: прокрутка их не трогает, потому что секции и собираются по прокрутке. Секции, ушедшие с экрана,
дособирает `abortRun`. Клик по «Пересобрать блок» сборку не пропускает.

### Спокойствие и качество

- **Перелив `.it`** стартует, когда секция собралась (`animation-play-state`). На первом экране он постоянный, в
  остальных секциях — два прохода, потом статичный градиент.
- **Дымный след** тише: альфа `0.022` / `0.035` на мобилке, жизнь 1.1–1.8 с.
- **Импульсы на схемах** в покое раз в 4.4 с, при наведении раз в 1.1 с.
- **Адаптивное качество** (`watchQuality`). Если два окна по 2 с подряд средний кадр дольше 24 мс, движок
  спускается на уровень: 1 — `.pt-lite`, без стеклянного размытия и дымного следа; 2 — ещё и частицы в 1×
  разрешении. Уровень хранится в `sessionStorage pt-lite`.
- **Пульт:** печатающийся статус `[data-pt-step]` скрыт от скринридеров (`aria-hidden`), иначе он зачитывался бы
  посимвольно. Кнопка «Пересобрать блок» доступна.

### Фазы частиц

`phGrid`, `phWire`, `phSkel`, `phText`, `phFade`, `phAmbient`, `phSettle`, `phObject`. Каждая готовит цели через
`fill(idx, gens, opt)`, переход размазан во времени (`sweep`).

Финал сборки решает `finish()`: если очередь пуста, секция с `data-pt-burst` уходит в `phAmbient`. Это разлёт:
частицы летят из букв в случайные точки экрана. Остальные секции уходят в `phSettle`: частицы догасают на месте, а
через 1.3–2 с, уже невидимыми, переносятся в случайные точки экрана (флаг `TP` — телепорт при переключении цели).

`measure(s)` перемеряет геометрию секции:
- `collectWords` — слова через `Range`;
- `glyphs` — пиксели букв;
- `frameRects` — рамки `.fr`;
- `blockRects` — блоки `[data-blk]`;
- `makeLines` — строки.

Замер дорогой, поэтому результат кэшируется в `s.geo` по ключу `s.geoKey`. В ключ входят `layoutGen` (растёт при
ресайзе и догрузке шрифтов), ширина окна, размер и положение секции, `document.fonts.status`. Если раскладку
меняешь как-то иначе, увеличь `layoutGen`.

- **Растр букв (`glyphs`) ленивый.** `measure` его не считает. Его один раз на геометрию считает `ensureGl(s)` в
  начале `phText`. Раньше шрифты догружались примерно через 0.2 с после старта, сбрасывали кэш, и полный замер
  с растром выпадал на стадию сетки первого экрана. Это давало рывок ~30 мс.
- **Буквы рисуются в компактный атлас**, а не на холст размером с секцию: слова кладутся «полками» (ширина 1024),
  точки переносятся обратно в координаты слова. Читать и перебирать приходится в разы меньше пикселей:
  ~28 мс → ~8 мс на первом экране в тестовой VM.
- **Догрузка шрифтов** (`onFonts`) только сбрасывает кэш. Стадию она не перезапускает, иначе все частицы разом
  дёргались бы к новым целям.

**Производительность цикла.** Невидимая свободная частица — это `M = 1`, `AT = 0`, `A < 0.01`. Такие частицы на
экран не попадают, поэтому в `frame()` их дрейф считается по очереди: каждый кадр обрабатывается четверть
(`i & 3`), с накопленным временем своей четверти (`lzT`). Сдвиг при прокрутке применяется каждый кадр. Видимые
частицы считаются как раньше. В простое это примерно на треть сокращает время кадра, картинка не меняется.

### Хуки для новых интерактивных элементов

Все сцены в карточках лежат в массиве `scenes`, его заполняет `PTScenes.create(root, env)` при старте. Каждая сцена —
объект `{ cv, wake(), sleep(), tick(dt), resize() }`. Повторный `wake()` (после пересборки секции) перезапускает
анимацию сборки сцены. `sleep()` ставит сцену на паузу до следующего `wake()`.

- `wakeSites(el)` вызывается, когда секция `el` собралась. Здесь лениво грузятся iframe-превью и
  будятся сцены, чей холст лежит внутри `el`.
- `frame(now)` — единый rAF-цикл. Первым делом `PTScroll.tick(now)`, потом частицы, `drawSmoke(dt, f)` и
  `tick(dt)` всех сцен. Свой `requestAnimationFrame` не заводить.
- `layout()` — ресайз. Здесь `fitSites()` и `resize()` всех сцен.
- `prefers-reduced-motion` (`rm`): всё сразу в финальном виде, без анимации. Сцены обязаны рисовать
  статичный кадр в `wake()` и `resize()`.

**Новая сцена:** функция в `scenes.js` по образцу `makeFlow`, регистрация в `PTScenes.create` по селектору
холста. Движок трогать не нужно.

## Готовые компоненты

### Объект в первом экране

`[data-obj]` — четыре формы из частиц (`SHAPES`: Brilliant, Lattice, Silicon, House) с переливом.
- Клик по блоку переключает форму, точки `[data-objdot]` выбирают конкретную.
- Точки собираются вместе с текстом. Их `span` помечен `.fr`, поэтому частицы обводят точки во время сборки,
  а сами точки скрыты до `s-done`. Так же стоит делать любые нетекстовые элементы управления.
- Автосмена каждые 7 с.

### Дымный след

Отдельный 2D-холст `[data-pt-smoke]` в половинном разрешении, лежит под контентом.
- До 520 цветных спрайтов, оттенок сдвигается по кругу.
- Создаётся в `emit()` из `onMove`, рисуется в `drawSmoke()`.

### Живые превью сайтов

```html
<span class="site"><span class="site-bar" aria-hidden="true"><i></i><i></i><i></i><span>домен</span></span><span class="site-view" data-site="URL"><iframe data-src="URL" …></iframe></span></span>
```

- **По умолчанию показывается снимок** `img.site-shot` (`assets/previews/*.jpg`). Он скрыт до `s-done` и
  проявляется вместе с текстом.
- **Живой сайт — только при намеренном наведении.** Курсор сам двигался по карточке и задержался на ней 0.6 с без
  прокрутки, либо на карточку перешли фокусом с клавиатуры (`liveSite` в движке). Тогда iframe грузится и
  проявляется поверх снимка. Когда курсор уходит, iframe гаснет и получает `visibility: hidden`, и браузер
  перестаёт его рисовать.
  Почему так: живое превью — целый сайт в 1440 px. Два таких сайта, рендерящиеся постоянно, были главной причиной
  лагов блока 02 и подвисания при сборке 02.2. Если страница просто проехала под неподвижным курсором, сайт не
  грузится. На тач-экранах живого превью нет, тап открывает сайт по ссылке.
- iframe рендерится в ширину 1440 и масштабируется под карточку (`fitSites`). `src` ставится только при первом
  включении.
- Новый сайт: добавь его в `tools/previews.mjs`, запусти `node tools/previews.mjs` и вставь `img.site-shot` первым
  ребёнком `.site-view`.
- Ссылка на сайт — `a.card-link`: растянута на всю карточку через `::after`, открывается в новой вкладке.
- `.site-bar` — «адресная строка» высотой 30 px над сайтом: три точки и домен. Превью начинается под ней
  (`.site-bar ~ .site-view { top: 30px }`), и `fitSites` масштабирует iframe уже под эту область. Строка
  появляется вместе с рамками на стадии `s-skel`. Домен — обычный текст: он собирается из частиц вместе с
  карточкой, а клик по нему уходит в `card-link`.
- Сайты сейчас: `https://resonara.ru/` и `https://useantares.com/`. Antares указан без `www`: на
  `https://www.useantares.com` GitHub Pages отдаёт сертификат на другое имя.

### Мини-сцена «ваш проект»

`makeMini(canvas[data-mini], env)` — внутри карточки по кругу собираются 4 демо-сайта (`TPL`):
- этапы: сетка → каркас → строки → контент → готовый экран → пыль;
- цикл одного сайта — 8.3 с;
- подпись этапа — `[data-mini-label]` (`data-pt-skip`);
- пауза, когда сцена вне экрана.

Все сцены устроены одинаково: свой 2D-холст, `wake()`, `tick(dt)`, `resize()`, пауза вне экрана, статичный
кадр при `rm`.

### Карточки-схемы: `makeFlow(canvas[data-flow="id"], env, cfg)`

Схемы автоматизации и интеграций. Конфиги лежат в `FLOWS` в `scenes.js`, ключ — значение `data-flow`:
`b24-digest`, `call-audit`, `tg-crm`, `ai-gateway`, а также случайные `your-process` (`rand: 'chain'`) и
`your-integration` (`rand: 'duplex'`).

- **Узлы:** `{ id, name, role, x, y }`, координаты центра в долях окна. Имя с « · » переносится, если не влезает.
  Если окно уже 340 px, включается компактный режим: шрифт 10 px, роль скрыта.
- **Связи:** `{ a, b, ev, k, grp, p }`. `ev` — подпись события. Значения `k`: `'f'` — прямая; `'r'` — обратный поток
  (импульс идёт назад по пройденному пути, при `duplex: true` он сиреневый); `'q'` — ответная ветка с вероятностью
  `p`. `grp` — из связей узла с одним `grp` импульс выбирает одну, остальные связи раздваивают его. Узел с
  `turn: true` разворачивает импульс назад (двусторонние интеграции).
- **Ритм:** узлы появляются слева направо, через ~1.5 с пошли импульсы: в покое раз в 4.4 с, при наведении на
  карточку раз в 1.1 с. Случайные схемы живут циклами по 7 с: сборка → 2–3 импульса → пыль → следующая. Подпись этапа
  выводится в `[data-flow-label]` (`data-pt-skip`).
- Все надписи рисуются на холсте. Для доступности у окна есть `role="img"` и `aria-label` со схемой словами.

### «Поток»: `makeFlowLight(canvas[data-flowlight], env)`

**Сейчас скрыт:** разметка карточки лежит в `<template data-hidden-card="flow-lock">` в ряду «Сайты». Холст из
`<template>` движок не видит, поэтому сцена не создаётся и не тратит ресурсы. CSS (`.frost`, `.nda`, `.flow-card`) и
код сцены остаются на месте. Чтобы вывести карточку, перенеси разметку из `<template>` в нужную секцию прямо в HTML.
Вставлять её через JS после старта нельзя: текст не получит `.ptx` (ловушка 1), а сцена не зарегистрируется.

Закрытый объект (карточка `[data-flowcard]`). Световые ленты-кривые Безье в цветах акцентов
сходятся в точку (0.62, 0.55). Поверх них лежит матовое стекло `.frost[data-frost]` с бейджем «NDA · показываем лично».
Стекло проясняется на `:hover`, на `:focus-within` и на `.is-open`. Класс `.is-open` ставит первый тап на
тач-экране, второй тап ведёт по ссылке, тап мимо карточки закрывает. Вместе со стеклом проявляется схема
`LOCK`: её рисует тот же движок схем, с плотной подложкой под плашками.

## Кейсы: правовое ограничение

Один из кейсов клиента нельзя рекламировать на сайте: в РФ это запрещено законом, штрафы от 50 тыс. ₽.
Репозиторий публичный, поэтому название сервиса, его домен и тематические слова **не пишем нигде в репозитории**:
ни на сайте, ни в документации, ни в коде.

На странице не должно быть:
- названия этого сервиса, его домена, ссылки на него и живого превью;
- слов, указывающих на тип сервиса, — ни в тексте, ни в `title`, `alt`, `aria-label`, `data-*`, комментариях и
  именах переменных.

Список запрещённых слов и доменов лежит в `tools/forbidden.local.txt`, по одному на строку. Файла нет в git: он
хранится на машине владельца, а при новом клоне его нужно попросить у владельца. `node tools/check.mjs` проверяет
по нему `index.html` и `assets/`. Если файла нет, проверка пропускается с предупреждением. Этот кейс подан только
как закрытый объект «Поток», без названия, домена, ссылки и превью. Сейчас карточка скрыта, см. раздел о «Потоке».

## Проверка после любых правок

1. `node tools/check.mjs` — прогон в Chromium с виртуальными часами (подробности в `tools/check.mjs`):
   - первый экран по этапам, каждая секция после сборки, 3 ширины: 1440, 1700, 390;
   - ошибки консоли, запрещённые слова в `index.html` и `assets/`;
   - сцены в карточках: пусты до сборки своей секции, нарисованы после, стоят на паузе вне экрана;
   - скриншоты в `tools/shots/`; эталон до правок блока «Объекты» — `tools/shots-before/`, только на машине владельца.
2. Открыть скриншоты и убедиться:
   - текст каждой секции проявился;
   - рамки видны;
   - на 390 px нет горизонтальной прокрутки и наложений.
3. Вручную в браузере: курсор оставляет цветной след под блоками, слова `.it` переливаются,
   «Пересобрать блок» пересобирает блок на экране.

## Не трогать без явной просьбы

По просьбе владельца уже меняли: тайминги (`HERO_K = 0.75`, `SEC_K = 0.9`, `PRESENT_K = 1`), яркость дымного следа,
режим перелива, `aria` у пульта. Дальнейшие правки этих мест — тоже только по явной просьбе.

- Тайминги `runHero` / `runSec`.
- Количество частиц и шейдеры.
- Палитру и шрифты.
- Сетку и краевые линии.
- Дымный след, перелив `.it`, объект первого экрана, пульт.
